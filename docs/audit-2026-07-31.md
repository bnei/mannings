# Codebase audit — 2026-07-31

Audit of `index.html` at `86f2015` (*Hide sweep panel title when sensitivity sweep is off*),
against the invariants stated in [CLAUDE.md](../CLAUDE.md), [README.md](../README.md),
[CONTEXT.md](../CONTEXT.md) and [docs/adr/](./adr/).

Everything below was checked against the live page served over HTTP
(`python -m http.server 8787`), not read off the source alone. Findings are ordered by
severity. **Nothing in this audit has been fixed** — this is the report, not the change.

---

## Findings

### 1. A crafted `sec` key in the fragment kills the page — MEDIUM

`init()` resolves the section type with a bare property read:

```js
setSection(SECTIONS[h.sec] || SECTIONS.trapezoid);
```

`SECTIONS` is an object literal, so this reads through `Object.prototype`. `SECTIONS.constructor`
is the `Object` function — truthy — so the `|| SECTIONS.trapezoid` fallback never fires, and
`setSection` proceeds with a value that has no `.view`. `applyIdentity` throws on
`sec.view.name`, `init()` aborts, and nothing after it runs.

**Reproduced** at `index.html?fresh=1#sec=constructor` on a genuine load: 0 field rows, empty
diagram, empty hint, primary value `—`, section `<select>` blank. The page is dead — not
degraded, dead. `__proto__`, `toString`, `valueOf` and friends do the same.

This directly contradicts the stated link policy: *"unknown keys are ignored rather than treated
as errors, so a link naming a section type this build doesn't have still opens on what it does
understand."* That promise holds for `#sec=egg` (correctly falls back) and fails only for names
inherited from `Object.prototype`.

No security consequence — the fragment never leaves the browser and nothing is injected into the
DOM — but a shared link is the tool's sharing mechanism, and this is a way for one to arrive dead.

**Fix:** one line, at the resolve site.

```js
var picked = Object.prototype.hasOwnProperty.call(SECTIONS, h.sec) ? SECTIONS[h.sec] : null;
setSection(picked || SECTIONS.trapezoid);
```

### 2. The capacity ceiling in the "no normal depth" error is rounded *up* — MEDIUM

`compute()` reports the ceiling through `fmt()`, which rounds to 4 significant figures in the
nearest-value sense:

```js
"No normal depth exists: this section conveys at most " + fmt(peak.Q) + " m³/s, ..."
```

For `D = 1, n = 0.03, S₀ = 0.01`, `Qmax = 1.1176065602`, which `fmt` renders as **1.118**.
Entering `Q = 1.1177` — genuinely above the maximum, correctly rejected — produces:

> No normal depth exists: this section conveys at most **1.118** m³/s, at a depth of 0.9382 m.

The user asked for 1.1177 and is told the section carries up to 1.118. The message reads as
self-contradictory, and the number it states is one the section cannot actually convey.
Reproduced live at `Q` = 1.1176 and 1.1177.

This matters more than ordinary display rounding because the value is being used as a *bound* the
reader is invited to compare against, not as a reported result. Rounding a capacity ceiling up
overstates capacity — the wrong direction for a number that may end up justifying a culvert size.
The same `fmt(peak.Q)` appears in the circle's *peak conveyance* caveat, where it overstates in
the same direction but is less acute, being a caveat rather than a rejection.

**Fix:** floor the ceiling to the displayed precision rather than rounding it, so the stated
bound is always one the section really achieves — a `fmtFloor()` sibling to `fmt()`, used
wherever a maximum is reported as a limit. Keep `fmt()` for measured results.

### 3. `/favicon.svg` is root-absolute and breaks the `file://` promise — LOW

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
```

The leading slash resolves against the origin root. Opened from `file://`, that is the
filesystem root — `file:///C:/favicon.svg` on this machine — so the icon 404s in exactly the
offline case the single-file shape exists to serve. It is also the only absolute path in the
file; everything else is self-contained.

Works on Cloudflare Pages because the site is deployed at the root, which is why it hasn't
surfaced.

**Fix:** drop the slash — `href="favicon.svg"`.

### 4. `stepCeiling` gives up when the crown is below one step of `y` — LOW

CLAUDE.md states the invariant plainly: *"The arrows cannot step a field to a value validation
would then reject."* For a closed section that holds only while `D` exceeds `y`'s step of 0.1 m.

```js
var k = Math.ceil(limit / st) - 1;
return k > 0 ? String(+(k * st).toFixed(10)) : null;
```

With `D = 0.05`, `k = ceil(0.5) - 1 = 0`, so the function returns `null` and `compute()` removes
the `max` attribute entirely. Confirmed: `stepCeiling` returns `null` at `D = 0.05` and `"1.9"`
at `D = 2`. The arrows can then step `y` to 0.1 ≥ `D`, which `circle.math.validate` rejects as
surcharge — the state the ceiling exists to prevent.

Compounding it, `stepFloor` puts `min = "0.1"` on `y` (one step, from the `positiveAsPoint`
domain), so on a 50 mm pipe the floor is already above the crown and no arrow-reachable value is
valid at all.

Narrow — sub-100 mm circular sections — and the `null` is a deliberate fallback, since a `max`
below `min` would be incoherent. But the invariant as written isn't unconditional, and a 50 mm
pipe is a real thing to type in. Worth either fixing (a finer step for `y`, or a ceiling that
falls back to a sub-step value) or narrowing the claim in CLAUDE.md to say where it holds.

### 5. An unrecognised `mode` key leaves both radios unchecked — LOW

```js
if (h.mode) modeRadios.forEach(function (r) { r.checked = (r.value === h.mode); });
```

Any truthy value that matches neither radio unchecks both. `currentMode()` then falls back to
`"depth"` and the tool computes correctly, but the radio group renders with **nothing selected**
until the user clicks a mode.

Reproduced at `#mode=xyz`: both radios `false`, results computed as depth mode, hash immediately
rewritten to `mode=depth`. Self-healing in the URL, but not on screen. Cosmetic, and mildly an
accessibility problem — a radiogroup with no selection reads as an unanswered required choice.

**Fix:** only apply the value if it matches a radio.

### 6. CLAUDE.md's recorded figure geometry is stale by one commit — LOW (doc drift)

The Hard constraints section records:

> `.figwrap` 1184×403 each with the sweep shown and 1184×831 with it hidden.

Measured at 1920×1080: **1184×404** with the sweep shown, **1184×891** with it hidden.

The 403→404 is sub-pixel rounding and not worth chasing. The 831→891 is real and traceable:
`86f2015` — the most recent commit — added `.figure .subhead.hidden` and the
`classList.toggle` that hides the "Sensitivity sweep" heading along with the chart. That returns
roughly 60 px to the cross-section when the sweep is off. The commit is correct; the recorded
number simply predates it (CLAUDE.md's mtime is 8 minutes before the commit's `index.html`).

Since these numbers are the evidence for a *stated requirement*, and the file argues they were
verified rather than tuned, leaving them stale erodes the one thing they're for.

**Fix:** update the two numbers, and note that hiding the sweep now also reclaims the subhead row.

### 7. Static `<title>` and `<meta name="description">` still say "trapezoidal" — LOW (drift)

```html
<title>Manning's equation — trapezoidal channel</title>
```

`applyIdentity()` overwrites `document.title` on every section change, so the tab is right in a
running browser. But the *served* markup names one of the two section types, and that is what a
crawler, a link preview, a no-JS reader and the browser tab before first paint see. The meta
description does mention both, but leads with the same framing.

**Fix:** make the static title section-neutral — "Manning's equation — channel sections" matches
CONTEXT.md's own heading — and let `applyIdentity` specialise it at runtime as it already does.

### 8. Results and errors are not announced to assistive technology — LOW (absent, not broken)

Flagging rather than proposing: there is no `aria-live` anywhere in the file. Every result,
warning and error is written into a `<div>` or `<span>` that a screen reader will not re-read.
For a tool whose entire output updates silently on each keystroke — including error states that
*hide* the results block — a sighted user sees the change and a screen-reader user gets nothing.

`aria-live="polite"` on `#results-body` and `aria-live="assertive"` on `#error` would cover it,
at no cost to layout. Not added here; noting it because it is the one gap where the page's
otherwise careful labelling stops short.

### 9. `history.replaceState` fires on every keystroke — INFORMATIONAL

`compute()` ends in `writeHash()`, which calls `history.replaceState`, and `compute()` is bound
to the `input` event of every field plus both sweep-range boxes. Sustained fast typing can
approach the rate limits browsers impose on history mutation — Safari's has historically been
~100 calls per 30 s, and it throws `SecurityError` rather than queuing.

Not reproduced here (Chromium, which throttles by queuing rather than throwing), so this is a
note rather than a finding. If it ever surfaces it will look like an exception on the last line
of `compute()` after the results have already painted. A trailing debounce of ~150 ms on
`writeHash` alone would remove the category without touching the compute path.

## Not findings

Recorded so they don't get re-raised:

- **No roots at exactly `Qmax`.** `normalDepths` returns `[]` at the tangency, since a double
  root produces no sign change. Inherent to bracketing, confined to the top 0.035% of the
  two-root band, and the correct answer everywhere above it. The *message* at that boundary is
  finding 2; the enumeration itself is sound.
- **`maxDischarge` called from `circle.view.conditions`.** The stated rule is that hydraulics
  never read `.view`. The reverse — view calling math — is the intended direction and is fine.
- **`readHash` splitting on the first `=` only.** Values are numbers and enum keys; no current
  or planned key can contain `=`. The agreed `pts=0,3;0.5,0;...` encoding for arbitrary sections
  doesn't either.
- **`:has()` and `color-mix()`** in the stylesheet. Both are Baseline 2023 and degrade to a
  missing highlight rather than a broken layout. Consistent with the no-build, no-dependency shape.
